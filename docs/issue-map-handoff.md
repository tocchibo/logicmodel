## 現在のプロトタイプの状態

`issue-map.html` は、AIが生成した `issue-map/v1` JSONを貼り付けて表示・編集するための別ページ。

描画層は、ELK.js の `layered` レイアウトで自動配置し、その結果をSVGとして描画している。

理由は、構造マップでは関係が一意に読めることが最優先であり、ELK layered の直交エッジルーティングでノード領域を避ける表示を作りやすいため。Cytoscape.js は自由度が高いが、今回の要件である「ノードの下をエッジが通らない表示」を保証しづらかった。

主な機能:

- `docs/test_issue_map.json` のサンプル読込
- JSONバリデーション
- ノード、関係、ループ、根拠の表示
- ノード追加、関係追加
- 選択したノード・関係の編集
- JSON保存、JSON読込、JSONコピー
- AI修正用プロンプトコピー
- 全幅キャンバスでの全体表示
- 16:9想定のSVG表示とSVG保存
- ELK layered によるノード配置と直交エッジルーティング
- 図上のエッジIDタグと右側の関係一覧による関係の一意復元

`issue-map.html` は `elkjs@0.11.1` をCDNから読み込む。Cytoscape.js と Viz.js は現在の `issue-map.html` では読み込んでいない。バックエンドやビルドステップは不要。

## 検証でわかったこと

検証では、以下が重要だとわかった。

- 構造マップでは、関係が一意に復元できない表示は不可。
- ノードの下をエッジが通る方式は、つながりを読み落とすため避ける。
- スクロール前提のキャンバス表示は不可。初期表示で全体像が見える必要がある。
- 因果の流れを壊すため、ELK layered の折り返し表示は採用しない。
- 高度な編集機能より、まずはきれいで一意に読める表示を優先する。
- 線だけに意味を背負わせず、ノードID、エッジID、右側の関係一覧を組み合わせる。
- 全関係表示は密度が高いため、選択周辺表示やループ表示で詳細を確認できる状態を残す。

SIIFの課題構造マップ例からは、次が重要だと整理した。

- 全体の所在を観点帯で見せる
- 関係を一意に復元できるようにする
- 線だけに意味を背負わせず、IDや一覧と組み合わせる
- ループや重要関係は必要に応じて強調する
- 最終的な美観は人が手修正できる余地を残す

## 次の方針

表示品質を最優先にする。高度な編集機能、ドラッグ編集、パン/ズームより、構造と関係が一意に読めることを優先する。

優先候補:

- 全関係表示時のエッジIDタグ密度調整
- エッジ経路がノード矩形を通っていないかの継続確認
- 全幅キャンバスでの文字サイズ、余白、16:9出力の継続調整
- 選択周辺表示とループ表示の視認性改善
- PowerPoint貼り付け用SVGの見え方確認
- 必要なら、表示専用の関係表・隣接表をキャンバス内にも追加する

## 現在の描画実装メモ

既存のJSONスキーマは維持している。

表示方針:

- 初期状態は全関係を表示する。
- ノードは観点ごとの色で区別する
- ノード配置とエッジ経路はELK.jsに任せる
- レイアウトは折り返しなしの一方向表示を基本にする
- 編集ペインは下段に置き、マップ表示を上段の全幅キャンバスにする
- エッジには `E01+` のようなIDタグを表示する
- 右側の関係一覧で `E01 N002 -> N001 +` のように関係を一意に復元できるようにする
- 選択周辺表示では、選択ノードまたは選択関係に関わるエッジだけを濃く表示する
- ループ表示では、選択ループのエッジだけを表示・強調する
